〇、背景、原则与资源约束
================================================================
背景：ICS 的设想是"收缩对外观干预敏感、对身份不敏感的方向"。已知（idAPR 阶段 A）：用"同一个框在干预前后的
  特征差"估计的前 2 个方向（下称"干预方向"），在 BDD 上装了约 37% 的跨域偏移，身份差异只有约 11%，沿它漂移
  不造成遗忘（恢复 0.3%）。本任务要产出可放进论文的图和指标，检验五件事：
  ① 真实天气反事实是否落在干预方向里（VKITTI2 同一辆车只换天气）；
  ② 干预本身不改变身份；
  ③ 干预方向反映的是全帧共享的环境因素；
  ④ 删掉干预方向后天气信息减少、身份信息基本不变；
  ⑤ 用干预方向训练的 ICS（C2/C3）是否让同一辆车跨天气更容易被认出。
原则：
  - 输出目录 /data1/liuyeqiang/ics_evidence_<时间戳>/（下文 $E）；不修改其他任务的目录；结果提交 GitHub experiments/ics_evidence/。
  - C2、C3、C4 正在占用 8 张卡训练，不得占用这些卡，也不得影响其进程。GPU 任务只用 nvidia-smi 显示完全空闲的卡；
    没有空闲卡就排队等待，先做 CPU 部分。
  - 判断标准在下面写明，做完后如实报告，不按结果挑选样本、种子、模型或子集；不符合标准也照实写。
  - 所有子空间都在 fit 视频上估计，指标都在 test 视频上计算（按视频划分，seed0，与之前相同）；只用 car。

已有输入：
  BDD 探针特征（含 clean/fap/photo/student 与剂量视图）：
    HF：/data1/liuyeqiang/damot_ics_followup_20261029/results/feats/HF_stage4_e5/
    F ：/data1/liuyeqiang/damot_rebuttal_20261026/results/ics_probe/feats/F_stage4_e5/
  脚本：仓库 tools/analysis/ics_probe_extract.py、ics_probe_analyze.py、ics_probe_drift.py；
       idAPR 的 tools/analysis/idapr_basis.py（label_free_bases）与阶段 A 结果 experiments/idapr/A/。

五类对照方向（各模型分别估计，m=2，第一方向记为 e1）：
  (INT) 干预方向：同一个框 (feat_view − feat_clean) 的协方差前 2 维，view ∈ {fap, photo, student}，不中心化
  (ICS) 该模型存储的 ICS：bank_pcs，QR 正交化
  (W)   天气 oracle：域间散度前 2 维（用标签，作上限）
  (ID)  身份 oracle：实例间散度前 2 维（用标签，作反例）
  (R)   随机 2 维，10 次平均（seed0）

第一部分：只用 CPU（现在就开始，约 1–1.5 小时）
================================================================
对 HF 和 F 两个模型分别做。

② 干预不改变身份（跨视图身份检索）
  沿用 P2 的检索任务（同一视频、gap=4、window=30、最多 4000 个查询、seed0）。
  报告：同视图 mAP（查询和图库都用 clean）；跨视图 mAP（查询用 clean，图库用 fap / photo / student，三种各报一次）；
       比值 = 跨视图 mAP / 同视图 mAP。
  标准：三种视图的比值都 ≥ 0.95。

③ 共同偏移（ICC）
  对每个方向，把 test 视频中每个 RoI 投影到 e1（另报：投影到整个 2 维子空间后的范数）。
  只取至少有 3 辆车的帧。ICC = 帧均值的方差 / 投影的总方差（按 RoI 计）。
  另报"按域均值"解释的方差比例：域均值的方差 / 总方差。
  标准：ICC(INT) − ICC(ID) ≥ 0.3。

④ 删除测试（β=1，离线）
  对每个方向，把特征在该子空间上的分量去掉（不重新归一化），在 test 视频上计算：
    5 类天气平衡准确率（分类器在 fit 视频上重新训练）、night vs clear_holdout_45v 二分类准确率、
    Fisher 比（域间散度迹 / 域内散度迹，car）、身份检索 mAP（同 P2）。
  报告每项相对"不删除"的变化。
  标准：INT 的 Fisher 比下降 ≥ 30%，且身份 mAP 变化在 ±1.0 以内；同时报告天气准确率的变化（不设门槛，如实写）。

第二部分：VKITTI2 真实天气反事实（GPU 推理，有空闲卡再做，约 1–2 小时）
================================================================
2.1 数据核对（CPU，先做）
  在仓库 rebuttal_20261026/code/configs/_base_/datasets/ 下找到 vkitti2_clone / fog / morning / overcast / rain / sunset
  的标注文件与 img_prefix，确认文件存在，并写入 $E/vkitti2_inputs.txt。
  配对规则：同一场景（scene）、同一帧号（frame_id）下，clone 与其他天气版本的 GT 框按 IoU ≥ 0.9 一对一匹配
  （VKITTI2 各天气版本的几何相同；不依赖 instance_id 是否一致）。
  报告每个天气版本可配对的框数；若某个版本少于 500 对，单独注明。
  若 VKITTI2 数据不在服务器上，跳过第二部分和第三部分，并在 SUMMARY 中写明。

2.2 抽特征
  模型：HF_stage4_e5 与 F_stage4_e5（BDD 上训练，直接用于 VKITTI2，不微调）；如果服务器上有在 VKITTI2 上训练的
  DAMOT 最终 checkpoint，也加上，并在表中单独一行。
  用 ics_probe_extract.py（--box-source gt），六个天气版本各作为一个 --domain，
  视图：clean、fap、photo（用于在 VKITTI2 上估计域内的干预方向），剂量视图关闭；
  抽样：全部场景，每个视频每 3 帧取 1 帧，最多 60 帧；car 类（VKITTI2 的类名按标注实际名称）。
  确保各天气版本抽到的帧号相同。

2.3 反事实捕获率（CCR）
  对每个配对的框：Δ = z(variant) − z(clone)（L2 归一化后的 clean 视图嵌入）。
  CCR(E) = Σ‖EᵀΔ‖² / Σ‖Δ‖²，按天气版本分别报告，并给出五个版本的平均。
  方向：用 BDD 特征（同一模型）估计的 INT、ICS、W、ID、R；另加
       INT-vk：在 VKITTI2 clone 版本上按同样方法（fap、photo 视图）估计的干预方向（不用天气配对信息）。
  另报：Δ 的总能量；Δ 与"同帧不同车之差"的能量比（衡量天气变化相对身份差异有多大）。
  标准：CCR(INT) ≥ 5 × CCR(R)，且 CCR(INT) > CCR(ICS)。

  图 A：反事实捕获率柱状图（横轴为六类方向，柱为五个天气版本的平均，误差线为版本间的标准差），
       虚线标出 m/D = 2/256。
